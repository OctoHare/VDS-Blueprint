# Руководство по участию в проекте «Феникс»

Спасибо за желание сделать «Проект Феникс» лучше! Любой вклад — от исправления опечатки до добавления новых проверенных скриптов — очень ценится.

## 🚀 Как можно помочь проекту?

1. **Нашли ошибку, опечатку или есть идея?** 
   Создайте **Задачу (Issue)** в разделе [Issues](https://github.com/OctoHare/VDS-Blueprint/issues) — это просто общественная тема/обращение, где можно описать проблему или предложить идею для обсуждения.

2. **Хотите сами внести правки в код или текст?**
   Отправляйте **Запрос на слияние (Pull Request)**. Вы делаете изменения у себя и отправляете их нам на проверку — мы посмотрим правки и в один клик добавим их в проект.

## ⚠️ Важное правило при отправке Pull Request

> **README.md генерируется автоматически из файла `docs/index.md`.**  
> Пожалуйста, **НЕ редактируйте `README.md` вручную!** Все правки текста и структуры нужно вносить строго в файл `docs/index.md` (или другие файлы в папке `docs/`).

## 📝 Требования к оформлению

* Сохраняйте общий стиль оформления Markdown.
* Добавляйте только **проверенные на практике** решения и рабочие ссылки.
* Пишите просто и понятно, без избыточных усложнений.

# Contributing Guidelines

Thank you for wanting to make the "Phoenix Project" better! Any contribution — from fixing a typo to adding new verified scripts — is greatly appreciated.

## 🚀 How can you help?

1. **Found a bug, typo, or have an idea?**  
   Create an **Issue** in the [Issues](https://github.com/OctoHare/VDS-Blueprint/issues) section to describe the problem or propose an idea for discussion.

2. **Want to contribute code or text changes yourself?**  
   Submit a **Pull Request (PR)**. Make your changes and send them for review — if approved, they will be merged into the project with a single click.

## ⚠️ Important Rule for Pull Requests

> **README.md is automatically generated from `docs/index.md`.**  
> Please **DO NOT edit `README.md` manually!** All edits to the text and structure must be made strictly in the `docs/index.md` file (or other files in the `docs/` folder).

## 📝 Style Guidelines

* Maintain the overall Markdown formatting style.
* Add only **field-tested** solutions and working links.
* Keep explanations simple, clear, and concise.
